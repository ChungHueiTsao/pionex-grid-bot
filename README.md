# pionex-grid-bot

派網（Pionex）網格交易自動化 — 先模擬、後上真單。策略選擇依據見下方「策略研究」。

## ⚠️ 風險告知

這是自動下單程式，接上真實 API Key 之後會動用真實資金。虛擬貨幣波動大，任何策略都可能虧損，過去的模擬/回測結果不代表未來績效。這不是投資建議，請自行評估風險與承受能力，資金規模請控制在你可以承受全部損失的範圍內。

## 目前狀態

- ✅ `pionex_client.py` — 派網 REST API 封裝（公開行情 + 私有帳戶/下單，簽名邏輯依官方文件 https://www.pionex.com/docs/api-docs/ 實作）
- ✅ `grid_strategy.py` — 網格策略引擎（純邏輯，不連交易所），內含三種策略：`GridEngine`(固定區間網格，需自己指定區間)、`run_trend_filtered()`(趨勢過濾網格，需自己指定區間)、`run_walk_forward()`(**目前預設/建議使用**——區間由程式每週自動用過去30天資料算出，不需要你自己猜，也不會有事後諸葛的偏誤)
- ✅ `simulate.py` — **模擬模式**，抓派網真實公開行情資料跑網格邏輯，全程不需要 API Key，不會下任何真單。預設用 `--strategy walk-forward`（不用給 `--lower --upper`），也可切 `trend-filtered` 或 `baseline` 搭配手動區間對照
- ✅ `ta_strategy.py` — 純技術指標策略引擎（不用網格），內含三種：`run_tiered_ma_strategy()`(三階梯多均線50/100/200日，**目前預設/建議使用**，+1818.8% vs 買入持有+1229.0%，8.9年回測，回撤還更低)、`run_ma_filter_strategy()`(單一200日均線濾網，+1003.4%，較簡單的備選) 與 `run_ta_strategy()`(EMA黃金交叉+ATR停損停利，回測-4.4%，僅供對照)
- ✅ `live.py` — 網格真單邏輯已完整寫好（下限價單、追蹤成交、觸發停損自動取消掛單+市價出清、狀態存檔可斷線續跑），**但沒有 API Key 前跑不起來**，且執行它、真正送出真單必須是你自己按下去
- ✅ `live_ta.py` — 技術指標策略真單邏輯（現貨市價單），`--strategy tiered-ma`(預設) / `--strategy ma-filter` / `--strategy ema-atr`(舊版對照)，安全機制與 `live.py` 相同（三道防呆），**同樣沒有 API Key 跑不起來，執行送出真單必須你自己按**

## 安裝

```bash
cd pionex-grid-bot
pip install -r requirements.txt
```

## 先跑模擬（現在就可以跑，不需要任何帳號）

```bash
python simulate.py --symbol BTC_USDT --capital 1000 --interval 1D --limit 200
```

預設用 `walk-forward` 策略，區間自動算，不用猜 `--lower --upper`。參數說明：
- `--grids`：網格數量（格數越多，單格利潤越薄，但成交越頻繁）
- `--capital`：模擬總資金（USDT）
- `--interval`：K 線週期（`1M 5M 15M 30M 60M 4H 8H 12H 1D`）
- `--limit`：抓幾根 K 線（最多 500）
- `--lookback-days` / `--recalibrate-every` / `--buffer-low` / `--buffer-high`：walk-forward 專用，控制區間怎麼從歷史資料算出來、多久重算一次
- 想測試自己指定的固定區間（例如你已經有想法）：加 `--strategy trend-filtered --lower 72000 --upper 88000`，但要注意這樣容易不小心把「看過走勢後回頭挑的區間」當成客觀結果（見下方「策略研究」第四輪）

輸出會列出每筆模擬成交、最終現金/持倉/權益/損益、是否觸發停損；`walk-forward` 模式還會多印一行「同期買入持有BTC」的對照數字，方便你判斷這個策略到底有沒有比躺著不動好。

## 風控參數（AI 團隊兩輪辯論後的共識，已寫進 `grid_strategy.py` 預設值）

| 參數 | 預設值 | 說明 |
|---|---|---|
| 單格資金比例 | 4%（3-5% 區間） | 避免單格波動過大影響整體 |
| 最大同時持倉網格資金比例 | 25%（20-30% 區間） | 避免單邊突破時同時套牢過多部位 |
| 整體停損 | 18%（15-20% 區間） | 總權益回撤達此比例，模擬引擎會自動全部平倉並停止 |
| 手續費率 | 0.05%（`fee_rate`，依你實際費率等級調整） | 影響單格獲利門檻 |

## 之後要上真單的步驟（已完成，現況記錄）

1. ✅ 已在派網開通 API（label `grid-bot-simulate-first`，Enable reading + Enable trading，未設 IP 白名單），連線已用 `get_balances()` 驗證成功
2. ✅ `.env` 已設定好 `PIONEX_API_KEY` / `PIONEX_API_SECRET`
3. 先用 `simulate.py`（網格）或 `ta_strategy.py`（技術指標）針對想測試的 symbol/參數多跑幾次，確認邏輯與參數你能接受
4. `live.py`（網格真單）與 `live_ta.py`（技術指標真單）都已完整寫好，各有三道防呆：`.env` 裡要打一段確認字串、指令要加 `--i-understand-real-money-is-at-risk`、執行時還要再手動打字確認一次——這是刻意設計成不會被誤觸發，Claude 不會替你按過這幾道關卡

```bash
# 技術指標真單（現貨、不做空）—— 預設用三階梯多均線（目前回測最佳）
python live_ta.py --symbol BTC_USDT --ma-short 50 --ma-mid 100 --ma-long 200 \
    --i-understand-real-money-is-at-risk

# 或用較簡單的單一200日均線濾網
python live_ta.py --strategy ma-filter --symbol BTC_USDT --ma-long 200 --position-pct 0.95 \
    --i-understand-real-money-is-at-risk

# 或用舊版 EMA+ATR（回測較差，保留供對照）
python live_ta.py --strategy ema-atr --symbol BTC_USDT --ema-fast 20 --ema-slow 50 \
    --atr-period 14 --stop-mult 2.0 --tp-mult 3.0 --position-pct 0.95 \
    --i-understand-real-money-is-at-risk
```

### `live_ta.py` 什麼情況會停止？注意事項有哪些？（2026-08-31 更新）

**會讓它停下來的情況：**
1. **整體停損（`--max-drawdown-pct`，預設 25%）**：跟策略本身的均線訊號無關，是額外加的一層防護——追蹤歷史最高權益，若目前權益從最高點回落超過這個比例，會自動市價全部賣出並**永久停止**這個迴圈（不會自動重啟）。這是因為三階梯多均線/單一均線濾網策略本身沒有像網格那樣內建整體停損，完全依賴均線訊號來降低曝險，回測上可能承受到 50.7%~62.7% 的回撤才會反應——這道防線是額外的保險，不是取代策略邏輯。
2. **你自己按 Ctrl+C**：只會停止迴圈，**不會**幫你平掉現有部位，重新執行程式可以從存檔的狀態接續。
3. **連續且反覆的錯誤**（例如網路持續中斷、API 持續異常）：程式會自動重試（間隔隨失敗次數拉長，最長到 15 分鐘），**不會**自己放棄，但如果你的電腦本身關機、睡眠、或斷網太久，程式就真的沒在跑了——這不是程式的問題，是「這台電腦有沒有持續開著、連著網路」的問題。

**不會讓它停止的情況（刻意設計）：**
- 均線訊號翻空手（0% 倉位）：這是正常的策略行為，程式會繼續跑、繼續每天檢查訊號，不會因為空手就停止監控。
- 單次網路/API 錯誤：會重試，不會直接放棄。

**你要自己注意的事**：
1. 這支程式要**持續在背景執行**才會運作——筆電闔上、電腦睡眠、重開機都會讓它停止監控（雖然重跑可以從存檔繼續，但空窗期間如果剛好該轉倉，會錯過）。長期掛著建議用不會自動休眠的機器（例如一台常開的電腦，或雲端小主機）。
2. `Ctrl+C` 或任何非預期關閉都**不會**自動平倉——如果你要暫停策略，記得自己決定要不要手動到派網把部位平掉。
3. 三個策略檔案各自獨立存檔（`live_tiered_ma_state.json` / `live_ma_filter_state.json` / `live_ta_state.json`），換策略執行前確認你看的是對的存檔、對的部位狀態。
4. 這是市價單（MARKET），會直接按當下市場價格成交，沒有滑價保護——正常情況下 BTC/USDT 流動性足夠，滑價很小，但极端行情下可能有落差。

### 全面漏洞盤點與修復（2026-08-31）

使用者要求全面盤點還有哪些缺口，AI 團隊（Groq、Gemini、OpenRouter）針對「小資金新手、單一現貨交易對、市價單、輪詢式、狀態存本地JSON」這個具體架構列出常見失敗情境。實際修復並用假的 API 客戶端模擬各種異常情況驗證（不動用真實帳戶，14 項測試全部通過）：

**架構性修正（一次解決多個問題的根本修法）**：原本三個策略都用本地存檔的「目前倉位」狀態來決定要不要交易，一旦這個狀態跟真實帳戶脫節（例如整體停損賣出後沒同步、或程式意外中斷），就會做出錯誤決策。**改成每次都直接用真實餘額反推目前倉位**，不再相信存檔裡的舊值——存檔只保留給人看的參考用途，不再是交易決策的依據。

**已修復的具體項目：**
| 問題 | 修復方式 |
|---|---|
| 整體停損賣出後，策略自己的倉位狀態沒同步歸零（原始bug） | 已修復——見上，且改成從真實餘額反推，就算漏同步也不會再有影響 |
| 下單途中發生例外（網路斷線等），但程式已經把「今天處理過了」記下來，導致當天訊號被跳過、永遠不會重試 | 只有在整個流程成功跑完才會記錄「今天處理過」，例外會讓下一輪重新嘗試同一天的訊號 |
| 本地 JSON 狀態檔寫到一半當機/斷電，導致檔案損毀，程式下次啟動直接當掉 | 改用「先寫暫存檔、再原子性更名」的寫入方式，不會有寫一半的中間狀態 |
| 狀態檔案損毀（例如手動編輯壞掉）導致程式無法啟動 | 讀取失敗會印出警告、視為空白狀態重新開始，不會直接崩潰 |
| 不小心開兩個視窗同時執行同一支程式，兩邊各自對同個帳戶下單 | 新增鎖定檔案機制，第二個實例會偵測到並拒絕啟動（Windows 用安全的行程查詢方式檢查，不會誤殺其他行程） |
| 手續費造成的極小額餘額（灰塵）反覆觸發下單失敗或無意義的小單 | 改用「金額門檻」判斷（低於 1 USDT 視為灰塵），不再用「等於 0」這種脆弱的判斷方式 |
| 下單完全沒有唯一識別碼，日誌難以追蹤是哪一次操作對應哪一筆真實訂單 | 每筆下單都加上獨立的 `client_order_id` |

**已知但沒有完全解決的項目（誠實揭露）：**
- **時間戳漂移**：如果你電腦系統時鐘跟真實時間差太多，簽名會被拒絕。Windows 預設會自動校時，風險較低，但沒有做到主動跟伺服器時間同步校正——如果之後真的頻繁遇到簽名錯誤，這是第一個要查的方向。
- **「網路逾時但其實訂單已送出」的不確定狀態**：目前的重試邏輯在極端情況下理論上可能造成重複下單（例如：送出下單請求、伺服器已受理，但回應在半路遺失，程式判定失敗後重試）。市價單金額固定用「餘額的某個比例」計算，重複下單的實際影響會被限制在一次額外的小額買賣，不會無限放大，但這不是完美的解法——完整解法需要用 `client_order_id` 查詢訂單真實狀態再決定要不要重試，目前只做到「有記錄」，還沒做到「重試前先查證」。
- **部分成交**：BTC/USDT 流動性通常足夠讓市價單一次成交完畢，但沒有針對「只成交一部分」做特別處理。

這些已知缺口對這個資金規模（$100-300）的實際影響有限，但要誠實列出來，不要讓你誤以為現在是「零風險」。

## 策略研究（AI 團隊 llm-council 兩輪辯論結論）

### 第一輪：五種策略類型比較

在網格 / DCA / 均值回歸 / 動量突破 / 資金費率套利 五種策略中，針對「小資金、新手、偏好先模擬」的條件，最終排序：
1. **網格交易**（本專案採用）— 派網原生支援、模擬最成熟、資金運用效率高
2. 定期定額 DCA — 風險最低，可搭配網格一起用
3. 均值回歸 — 需自行接 API + 指標，中等難度
4. 動量突破 — 勝率較低、假突破多
5. 資金費率套利 — 理論勝率高但需要合約權限/保證金管理/清算風險，**不建議新手第一個策略就做這個**

### 第二輪：網格策略本身還能不能更好？（2026-08-31，真實回測驗證）

拿真實 BTC/USDT 歷史K線資料回測固定區間網格，發現崩跌段（2025/10/06→2026/06/30，現貨跌53%）會虧到 -10.1%。把這個實際數字丟回 AI 團隊做兩輪辯論，得到並驗證了兩個具體改進方案：

| 情境 | Baseline 固定網格 | **策略A 趨勢過濾網格** | 策略B ATR動態網格 |
|---|---|---|---|
| 上漲段 | +1.76% | +1.43% | +1.32%（236筆成交） |
| 高檔震盪 | +1.93% | -0.84%（提早防禦出場） | -3.14%（133筆成交） |
| 崩跌段 | -10.10% | **-0.45%** | -0.80% |
| 近期回升 | +1.15% | +0.98% | +2.66%（135筆成交） |
| **四情境加總** | **-5.26%** | **+1.12%** | +0.04% |

**結論：採用策略A（趨勢過濾網格），已成為 `simulate.py` 預設策略**，實作於 `grid_strategy.run_trend_filtered()`：
- 規則：`close < SMA(30)` 時暫停新買入（賣出照常）；`close` 比 SMA(30) 低超過 5% 且有持倉，強制全平倉防禦性出場
- 策略B（ATR動態網格）雖然理論上更精緻，但523筆成交（vs A的45筆）在真實交易中代表遠超模擬能反映的滑點/API延遲/斷線風險，且淨報酬也沒有比較好，AI團隊三個模型一致認為不適合小資金新手

**已知限制（誠實揭露，不是「保證有效」）：**
- SMA(30) 是資料只有~500根日K的妥協（AI團隊原本建議SMA(200)），效果比較接近「短期防禦開關」而非「長期趨勢判斷」，未來資料夠長（2年以上）應改測 SMA(50-100)
- 高檔震盪情境的 -0.84% 是「事後諸葛」式的合理防禦代價（用它換到崩跌段少虧9.65個百分點），但若當初沒有接著崩盤，這筆錢就是白虧的
- 只驗證了這一段真實歷史路徑，沒有做過壓力測試；長時間盤整可能讓這個策略被反覆洗盤（whipsaw）——這是目前最需要留意的風險

### 第三輪：等比網格間距（2026-08-31，真實回測驗證）

網路搜尋業界公開資料（Pionex部落格、Bitsgap、DEXTools）後，AI團隊一致建議把網格從「等差間距」（每格固定價差）改成「等比間距」（每格固定百分比），理由是這更符合報酬率邏輯、且低價位格子較密集能提升資金效率。**注意：其中一個模型（Groq）在回答中編造了看起來很精確的來源和統計數字（假的文章標題、發表日期、Sharpe Ratio），這些查無實據，已被排除，不採信任何未經 Claude 實際回測驗證的數字。**

實際拿真實資料回測（`GridConfig.spacing`），四情境全部小贏：

| 情境 | 等差（原本） | **等比（新，已設為預設）** | 差異 |
|---|---|---|---|
| 上漲段 | 1.43% | 1.48% | +0.05% |
| 高檔震盪 | -0.28% | 0.12% | +0.40% |
| 崩跌段 | -1.41% | -1.35% | +0.06% |
| 近期回升 | 0.96% | 1.31% | +0.35% |
| **四情境加總** | **0.70%** | **1.56%** | **+0.86%** |

改善是真實但溫和的，已設為 `GridConfig` 與 `simulate.py` 的預設值（`--spacing arithmetic` 可切回對照）。

**AI團隊對「大神方法」的一致結論：不存在勝率90%以上或穩賺不賠的神奇方法。** 網格交易本質上是在「賣波動率」，機構交易者的優勢來自極低手續費與即時對沖能力，不是什麼小資金散戶能複製的公式。我們目前的做法（趨勢過濾+等比網格+風控參數）已經接近小資金自動化交易的合理上限，之後的優化空間屬於「錦上添花」而非「生存問題」。

### 第四輪：修正「事後諸葛」偏誤，誠實回測（2026-08-31）

使用者問「總報酬只有1%多會不會太少」，戳破了一個重要的方法論漏洞：**前面第二、三輪的四個情境，價格區間都是 Claude 事後看著那段期間實際走勢去設定的**（例如已知會漲到118k才把上限設120k），這是典型的「未來函數」偏誤，backtest 數字會比真實情況好看。

AI 團隊三個模型（Groq、Gemini、OpenRouter）確認：+1.56% 換算年化只有約1.1%，比美金活存/國庫券利率（4-5%年化）還低，確實偏低；且一致認為不該再疊加 RSI/MACD/布林通道當買賣訊號（容易在震盪行情中製造假訊號、且比特幣價格不是常態分布，布林通道的統計假設不成立），真正該修正的是用誠實、不偷看未來的方式設定區間。

**修正後（`run_walk_forward()`）：區間改成每週只用「過去30天實際高低點 ×buffer」自動計算，整段~500天單次連續複利跑（不再切成四段各自重設$1000）：**

| | 網格策略（誠實回測） | 同期單純買入持有BTC |
|---|---|---|
| 2025/04/19 → 2026/08/31（500天） | **-7.00%** | **-8.93%** |
| 最大回撤 | 11.4% | （現貨本身跌幅達 -53%） |

**+1.56% 是有偏誤的數字，不要採信；-7.00% 才是誠實答案。** 這段期間 BTC 本身是下跌的（12.4萬跌到5.8萬又反彈回7.7萬），網格策略沒有「賺錢」，但比單純持有少虧了 1.93 個百分點、且最大回撤遠低於現貨本身的跌幅——它的價值是「盤整/下跌期少虧一點」，不是「穩定獲利」。**這也附帶抓到 Gemini 在前一輪回答中編造了『同期BTC從1.6萬漲到6-7萬、+300%』的假資訊**，跟這份真實資料完全對不上，已排除不採信。

`run_walk_forward()` 已成為 `simulate.py` 的新預設策略，不再需要手動指定 `--lower --upper`。`run_trend_filtered()`（第二輪的版本）仍保留，適合你已經有明確理由想測試特定區間時使用，但務必留意時間點——不要看著已經發生的走勢回頭挑區間。

### 第五輪：純技術指標策略（不用網格）+ 長期（8.9年）比較（2026-08-31）

使用者問：能不能完全不用網格機制，改用技術指標直接判斷停損停利點？AI團隊（Groq/Gemini/OpenRouter）一致建議「趨勢跟隨 + ATR停損停利」方向，三個模型給的具體規則略有差異（SuperTrend、唐奇安通道突破、雙均線交叉），Claude 綜合實作成 `ta_strategy.py`：

**規則**（現貨、不做空、單一部位）：EMA(20) 上穿 EMA(50)「黃金交叉」進場；出場條件（任一觸發）：跌破「進場價 − 2×ATR(14)」停損、漲破「進場價 + 3×ATR(14)」停利、或 EMA(20) 下穿 EMA(50)「死亡交叉」。

同時把資料拉到派網最早可查的歷史（**2017-10-26**，超過原本 500 天的範圍），做真正的長期比較，三種做法都從 $1000 本金、同一起點開始：

| | 長期報酬（2017/10/26–2026/08/31，8.9年） | 最大回撤 |
|---|---|---|
| **單純買入持有 BTC** | **+1223.8%** | 83.5% |
| 網格（walk-forward誠實版） | -18.8%（觸發18%停損後永久停止，之後就一直空手） | 22.7% |
| 技術指標趨勢跟隨（EMA+ATR） | -4.4% | 43.6% |

互動圖表：https://claude.ai/code/artifact/bf0bb4bf-2185-400d-8eda-7e93edb71b6a

**這是本專案目前最重要的發現，必須誠實面對：拉長時間看，兩個主動交易策略都大幅跑輸單純買入持有。** 原因是 BTC 這 9 年是結構性大多頭，任何「落袋為安、觸發停損離場」的機制，都會在某個時間點離開市場，然後錯過後面巨大的複利漲幅——網格在 2019 年觸發永久停損後就沒再進場，完美錯過了後面的整段大多頭；技術指標策略雖然有嘗試重新進場，但頻繁被洗掉（EMA交叉+較緊的ATR停損在BTC的高波動下容易假突破），最終還是跑輸。

**結論不是「不要用這些策略」，是要誠實理解取捨**：單純持有的代價是要承受 83.5% 的帳面最大回撤（也就是說如果 2018 年最低點你正好需要用錢，帳面上會虧超過八成）；網格和技術指標策略犧牲了長期複利，換來的是回撤壓得比較低、心理壓力比較小。這個 trade-off 沒有標準答案，取決於你的風險承受度與資金用途，不是「哪個比較好」的技術問題。

### 第六輪：問題出在哪裡？拿掉緊停損，換成單純均線濾網（2026-08-31）

使用者質疑 -4.4% 不是正報酬，問 GitHub/X 上有沒有更好的公開策略。**先聲明：網路上流傳的策略絕大多數是資料過度擬合的產物，沒有經過誠實回測就不該相信**——即使 Freqtrade（GitHub 星數最高的開源交易機器人，5.3萬星）這類受歡迎的專案，裡面的策略檔案也需要自己驗證，不能因為受歡迎就當作有效。

與其到處找「神策略」，先檢查自己已經做的東西哪裡出錯：拿同一段 8.9 年真實資料，額外測了兩個更簡單的方案：

| 策略 | 報酬 | 最大回撤 |
|---|---|---|
| 買入持有 | +1228.5% | 83.5% |
| **200日均線濾網**（`run_ma_filter_strategy()`，**現為 `live_ta.py` 預設**） | **+1003.4%** | **62.7%** |
| DCA（每週定期定額，不賣出） | +395.2% | 67.5% |
| EMA+ATR趨勢跟隨（第五輪版本） | -4.4% | 43.6% |

**找到問題根源：EMA+ATR 版本的「2倍ATR停損」設得太緊**，在 BTC 的高波動下會被頻繁洗出場（獲利還沒滾大就被甩掉），因而錯過後續的大波段複利。拿掉緊停損、只保留「站上200日均線就持有、跌破就全部出場」這個最單純的濾網，幾乎複製了買入持有 82%的報酬（1003.4/1228.5），但最大回撤少了 21 個百分點——這是目前為止風險調整後表現最好的主動策略，已經設為 `live_ta.py --strategy ma-filter`（預設值），`--strategy ema-atr` 保留舊版供對照。

**這次的教訓不是「找到更聰明的指標」，是「拿掉一個過度精細的風控機制」**——有時候更少的干預、更有耐心的濾網，比更緊的停損更有效。

### 第七輪：三階梯多均線倉位（2026-08-31，目前最佳結果）

使用者問還有沒有更好的方法，AI團隊（Groq、Gemini，兩個都收斂到同一個方向）建議：把「站上均線全倉、跌破均線空手」這種二元決策，改成用**三條均線（50/100/200日）分層決定持倉比例**，而不是只看一條 200 日均線的全有全無。

規則：站上 50日、100日、200日均線全部之上 → 持有 100%；只站上 200日均線（但跌破50或100日）→ 持有 50%；跌破 200日均線 → 空手 0%。切換等級才交易，不是每天都動。

實際回測（同樣 2017/10/26–2026/08/31，8.9年）：

| 策略 | 報酬 | 最大回撤 |
|---|---|---|
| 買入持有 | +1229.0% | 83.5% |
| 200日均線濾網（第六輪） | +1004.5% | 62.7% |
| **三階梯多均線（50/100/200日）** | **+1818.8%** | **50.7%** |

**這是目前唯一一個同時贏過買入持有報酬、又降低最大回撤的策略**——兩個維度同時贏很罕見，所以特別做了參數穩健性檢查（換 5 組相近週期：40/90/180、60/110/220、30/80/160、50/150/250），結果全部落在 +1430%~+1827%、回撤 44%~51% 之間，沒有崩潰，證明不是套中單一組神奇參數的過度擬合。

已實作為 `ta_strategy.run_tiered_ma_strategy()`，正式設為 `live_ta.py` 的新預設策略。

**誠實的保留態度（一定要講）**：這個結果雖然通過了參數穩健性檢查，但終究**只在同一條真實歷史路徑（2017-2026 的這一段 BTC 價格走勢）上驗證過**。每多做一輪優化，都是在同一段已知歷史上再挑一次，即使沒有刻意調整日期區間、即使參數穩健，也無法完全排除「剛好適合這段特定歷史」的可能——真正的樣本外驗證，只有等未來的真實價格走勢發生才算數。不要把這個數字當成保證，這只是「目前為止在這段歷史上，風險調整後表現最好的一個做法」。
